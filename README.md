# 《今晚不要填写事故报告》

类型：职场日常恐怖 / 因果链推理 / 自由文本语义判断 / 多结局网页解谜

## 核心体验
- 事故先以约 7 秒的监控动态短片出现，随后进入事故报告生成与调查。
- 监控画面采用统一的灰度低饱和办公 CCTV 风格：保留时间戳、机位标签与轻微信号噪声，但不再使用密集白色扫描线遮挡主体。
- 茶水间、消防楼梯、仓储区、一楼通道、测试区与未知事件六段监控均重新整理构图与可读性；茶水间能直接辨认饮水设备、人员与环境，测试区在“清场”后不再出现工作人员。
- 主界面改为浅灰白的企业内部行政系统风格，以纸面表单、表格和办公软件结构为主，不再以大面积深色渐变、玻璃拟态和霓虹配色作为视觉主体。
- 玩家填写事故因果与处置思路，不要求精确标准句，只判断核心方向。
- 语义判定分 PASS / PARTIAL / MISS：PARTIAL 不计完整失败；连续 2 次 MISS 才提醒玩家主动点击提示。
- 三级提示支持历史回看，不会自动弹出答案。
- 中期由“阻止事故”升级为“理解事故链和经济损失模型”。
- 第一次制造人员伤亡为 0 的受控设备事故后，系统启动管理员权限审查。
- 后半段权限被收回，玩家改用纸质授权、物业旧工单、打印邮件等线下证据。
- 多结局：重写模型 / 关闭系统 / 公开证据 / 继续提交。

## 运行
推荐通过静态 HTTP 服务器运行，例如：
`python -m http.server 8080`

或部署到 GitHub Pages / Cloudflare Pages。

## Cloudflare（可选）
前端本地语义规则已经能够完整通关。复杂中文表达可用 `worker/worker.js` + Workers AI 兜底，详见 `worker/README.md`。

## 发布
Windows 双击 `build_release.bat`。脚本会检查核心文件，若系统存在 Node.js 则执行 JS 语法检查，然后生成 `release` 目录。
